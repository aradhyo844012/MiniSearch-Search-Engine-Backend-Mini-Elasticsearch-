Debugging Open Source Contribution: A Field Guide

When something goes wrong around Open Source Contribution, resist the urge to guess. Work through the problem in order.

Step 1: reproduce the problem with the smallest possible example.
Step 2: list the usual suspects: opening huge pull requests, ignoring contribution rules, and expecting instant replies.
Step 3: revisit forks and pull requests, since misunderstandings there cause many bugs.
Step 4: use GitHub or similar tools to look inside.
Step 5: write a test that fails because of the bug and passes after the fix.

Many bugs involving Open Source Contribution in work such as building a portfolio come down to the first suspect on the list. Check the simple causes before suspecting anything exotic.

Finally, start with documentation fixes or small bugs. It prevents a surprising number of repeat problems.
