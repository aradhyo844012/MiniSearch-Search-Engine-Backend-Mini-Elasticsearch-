API Design Principles Tips from Experienced Engineers

Engineers who work with API Design Principles regularly tend to repeat the same advice. Here it is.

1. Be careful with this one: leaking internal details.
2. Test the case of public platforms early, before the design hardens.
3. Reach for OpenAPI first, and only then evaluate alternatives such as Postman.
4. When something behaves strangely, revisit clear errors before anything else.
5. Do not skip consistent naming; everything else builds on it.

None of these tips needs special equipment, and all of them apply to internal service contracts as well.
