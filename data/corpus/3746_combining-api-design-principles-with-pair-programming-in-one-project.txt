Combining API Design Principles with Pair Programming in One Project

Real projects rarely use one idea in isolation. This article shows how API Design Principles and Pair Programming can work together in a single project.

API Design Principles is guidelines for making APIs consistent, predictable and easy to use. Pair Programming is two developers working together at one computer on the same code.

Imagine a project that involves public platforms and teaching new teammates. API Design Principles brings consistent naming, while Pair Programming brings driver and navigator.

A sensible plan is to start with OpenAPI for the API Design Principles part and VS Code Live Share for the Pair Programming part, and to keep the two sides connected through a small, well-tested interface.

Be prepared for combined risks: inconsistent responses on one side, and fatigue from long sessions on the other.

Picture the whole as the controls of a car that behave the same in every model, working alongside a pilot and co-pilot who check each other's decisions.

Two habits help: first, write the documentation before the implementation; second, swap roles every twenty to thirty minutes.
