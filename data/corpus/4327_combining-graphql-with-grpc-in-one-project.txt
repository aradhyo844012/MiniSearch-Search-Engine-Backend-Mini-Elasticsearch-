Combining GraphQL with gRPC in One Project

Real projects rarely use one idea in isolation. This article shows how GraphQL and gRPC can work together in a single project.

GraphQL is a query language for APIs that lets clients ask for exactly the fields they need. gRPC is a framework for fast remote procedure calls using typed contracts.

Imagine a project that involves mobile apps with limited bandwidth and service-to-service calls. GraphQL brings schema, while gRPC brings protocol buffers.

A sensible plan is to start with Apollo for the GraphQL part and protoc for the gRPC part, and to keep the two sides connected through a small, well-tested interface.

Be prepared for combined risks: unbounded query depth on one side, and poor browser support without a proxy on the other.

Picture the whole as ordering a la carte instead of picking a fixed set menu, working alongside a phone line with a pre-agreed script for every call.

Two habits help: first, use a data loader to avoid N+1 queries; second, never reuse or renumber field numbers in a proto file.
