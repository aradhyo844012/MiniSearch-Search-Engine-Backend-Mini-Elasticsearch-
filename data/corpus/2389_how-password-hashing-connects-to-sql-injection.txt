How Password Hashing Connects to SQL Injection

Password Hashing and SQL Injection are closely connected parts of Security. Seeing how they fit together helps you learn both faster.

A project involving user login systems may also involve securing login forms. In such a project, salts and parameterized queries often influence each other.

Start with Password Hashing: the term refers to storing passwords as one-way hashes so the originals are never kept. Then look at SQL Injection, which refers to an attack where malicious input changes the meaning of a database query.

A useful exercise is to take one example, such as protecting data after a breach, and explain how input validation would change the design.

Common problems are shared too. For Password Hashing, watch for this: reusing salts. For SQL Injection, watch for this: using admin accounts for the app. Keeping dependencies updated removes a large share of known risks.

Spend a few hours on each topic, then combine them in one small project using bcrypt or prepared statements.
