Debugging Topological Sorting: A Field Guide

When something goes wrong around Topological Sorting, resist the urge to guess. Work through the problem in order.

Step 1: reproduce the problem with the smallest possible example.
Step 2: list the usual suspects: ignoring cycles, assuming the order is unique, and mixing up edge directions.
Step 3: revisit directed acyclic graphs and in-degree counts, since misunderstandings there cause many bugs.
Step 4: use Python graphlib or similar tools to look inside.
Step 5: write a test that fails because of the bug and passes after the fix.

Many bugs involving Topological Sorting in work such as build systems come down to the first suspect on the list. Check the simple causes before suspecting anything exotic.

Finally, check for cycles first so you can report a clear error. It prevents a surprising number of repeat problems.
