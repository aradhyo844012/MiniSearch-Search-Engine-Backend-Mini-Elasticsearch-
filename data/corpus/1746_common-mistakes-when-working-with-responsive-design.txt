Common Mistakes When Working with Responsive Design

Almost everyone makes a few avoidable errors when first working with Responsive Design. If you build software for long enough, you will run into Responsive Design. The term refers to building pages that adapt smoothly to phones, tablets and large screens.

Three issues come up again and again: testing only on one screen size; tiny touch targets; and horizontal scrolling. Knowing them in advance saves hours of debugging.

Consider the first problem: testing only on one screen size. A short test or a careful review comment usually catches it. The second problem is similar: tiny touch targets. The third problem is this: horizontal scrolling. It tends to appear only once a project grows, so it is worth planning for early.

Keep an eye on this risk during code review: testing only on one screen size. Start small by applying Responsive Design to one case, such as websites used on many devices, before rolling it out more widely.

With steady practice, Responsive Design will stop feeling abstract and become a tool you reach for naturally.
