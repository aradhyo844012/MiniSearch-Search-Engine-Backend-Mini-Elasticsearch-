Combining Open Source Contribution with Developer Portfolios in One Project

Real projects rarely use one idea in isolation. This article shows how Open Source Contribution and Developer Portfolios can work together in a single project.

Open Source Contribution is helping improve public software projects by fixing bugs, writing documentation or adding features. Developer Portfolios is a collection of projects and writing that shows what a developer can build.

Imagine a project that involves building a portfolio and applying for internships. Open Source Contribution brings forks, while Developer Portfolios brings projects.

A sensible plan is to start with GitHub for the Open Source Contribution part and GitHub Pages for the Developer Portfolios part, and to keep the two sides connected through a small, well-tested interface.

Be prepared for combined risks: ignoring contribution rules on one side, and no explanation of decisions on the other.

Picture the whole as helping repair a shared public library, working alongside a shop window displaying your best work.

Two habits help: first, start with documentation fixes or small bugs; second, feature a few polished projects rather than many half-finished ones.
