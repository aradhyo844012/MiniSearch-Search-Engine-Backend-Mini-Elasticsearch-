Combining CSRF with Security Headers in One Project

Real projects rarely use one idea in isolation. This article shows how CSRF and Security Headers can work together in a single project.

CSRF is an attack that tricks a logged-in user's browser into sending unwanted requests to a site. Security Headers is HTTP response headers that tell browsers to enforce extra protections.

Imagine a project that involves protecting forms and hardening websites. CSRF brings session cookies, while Security Headers brings Strict-Transport-Security.

A sensible plan is to start with Django CSRF middleware for the CSRF part and securityheaders.com for the Security Headers part, and to keep the two sides connected through a small, well-tested interface.

Be prepared for combined risks: skipping tokens on cookie-based APIs on one side, and breaking embeds on the other.

Picture the whole as a forged letter that a bank clerk stamps because your ID is already on file, working alongside safety instructions printed on the packaging of every page.

Two habits help: first, combine SameSite cookies with anti-CSRF tokens; second, test the headers on every environment.
