Questions to Ask About Data Quality Checks in Code Review

Reviewing code that involves Data Quality Checks is easier with a short list of questions. Keep these in mind as you read the diff.

- Have we avoided this problem: no ownership of failures?
- Would a test catch checks only at the end of pipelines if it appeared later?
- Does the code handle the case of protecting dashboards correctly?
- Does this change respect null checks, or does it work around it?
- Is Great Expectations used consistently, or are we mixing approaches?
- Have we considered alerts nobody reads?

Good reviews of work on Data Quality Checks are specific, kind and focused on freshness, not on personal style.
