Combining Fuzz Testing with Chaos Engineering in One Project

Real projects rarely use one idea in isolation. This article shows how Fuzz Testing and Chaos Engineering can work together in a single project.

Fuzz Testing is feeding programs random or malformed input to uncover crashes and security bugs. Chaos Engineering is deliberately causing failures in a system to learn how it responds.

Imagine a project that involves testing parsers and testing resilience. Fuzz Testing brings input generation, while Chaos Engineering brings steady state.

A sensible plan is to start with AFL++ for the Fuzz Testing part and Chaos Monkey for the Chaos Engineering part, and to keep the two sides connected through a small, well-tested interface.

Be prepared for combined risks: crashes that cannot be reproduced on one side, and having no steady-state metrics on the other.

Picture the whole as shaking a machine hard to see what rattles loose, working alongside a fire drill where you secretly block one exit.

Two habits help: first, keep every crashing input as a regression test; second, start with small experiments in a test environment.
