How Code Review Connects to Technical Debt

Code Review and Technical Debt are closely connected parts of Software Engineering. Seeing how they fit together helps you learn both faster.

A project involving catching bugs early may also involve deciding when to cut corners. In such a project, pull requests and shortcuts often influence each other.

Start with Code Review: the term refers to having teammates examine changes before they are merged. Then look at Technical Debt, which refers to the future cost of shortcuts taken in code, design or documentation.

A useful exercise is to take one example, such as sharing knowledge, and explain how interest would change the design.

Common problems are shared too. For Code Review, watch for this: vague comments. For Technical Debt, watch for this: hiding it from stakeholders. Teams succeed when they agree on a few simple practices and follow them consistently.

Spend a few hours on each topic, then combine them in one small project using GitHub pull requests or SonarQube.
