Open Source Contribution vs Technical Writing: Which One Should You Learn First?

Learners often ask whether to study Open Source Contribution or Technical Writing first. Both sit in the area of Developer Career and Tools, so the honest answer is that it depends on your goals.

Open Source Contribution is helping improve public software projects by fixing bugs, writing documentation or adding features, and it is closely tied to forks and pull requests. Technical Writing, by contrast, is explaining technical ideas clearly in writing for a chosen audience, and it is closely tied to audience and structure.

Choose Open Source Contribution first if you care about building a portfolio or learning from experienced maintainers. Choose Technical Writing first if you care about documentation or blog posts.

Think of Open Source Contribution as helping repair a shared public library, and of Technical Writing as giving directions to a stranger. The two pictures are very different, which is a useful reminder that the topics solve different problems.

Both have traps. With Open Source Contribution, avoid opening huge pull requests. With Technical Writing, avoid assuming too much knowledge.

A good habit for Open Source Contribution is to start with documentation fixes or small bugs. A good habit for Technical Writing is to state the main point in the first two sentences.
