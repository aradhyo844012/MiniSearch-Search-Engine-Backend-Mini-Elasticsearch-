Questions to Ask About Stored Procedures and Triggers in Code Review

Reviewing code that involves Stored Procedures and Triggers is easier with a short list of questions. Keep these in mind as you read the diff.

- Is triggers clear to someone reading the code for the first time?
- Does the code handle the case of enforcing rules close to the data correctly?
- Have we considered hidden logic that surprises developers?
- Could we keep triggers small and well documented?
- Is PL/pgSQL used consistently, or are we mixing approaches?
- Would a test catch hard-to-test code if it appeared later?

Good reviews of work on Stored Procedures and Triggers are specific, kind and focused on parameters, not on personal style.
