Myths and Facts About Password Hashing

A lot of folklore has built up around Password Hashing. Some of it is true, and some of it is not. If you build software for long enough, you will run into Password Hashing. The term refers to storing passwords as one-way hashes so the originals are never kept.

Write a few tests that show how Password Hashing should behave. Tests double as documentation for your teammates. Practice salts with small exercises until it feels natural.

Myth: Password Hashing is only for experts.
Fact: beginners can use it effectively once they understand salts and slow hash functions.

Myth: Password Hashing is only useful in very large systems.
Fact: small projects such as user login systems benefit as well.

Myth: one tool does everything.
Fact: bcrypt, Argon2, and scrypt make different trade-offs, so the right choice depends on the project.

Myth: mistakes with Password Hashing are always obvious.
Fact: subtle problems happen, for example using fast hashes like plain SHA-256.

None of this needs special hardware or expensive software. A laptop, curiosity and a few small experiments are enough to get comfortable with Password Hashing.
