Debugging Command Line Productivity: A Field Guide

When something goes wrong around Command Line Productivity, resist the urge to guess. Work through the problem in order.

Step 1: reproduce the problem with the smallest possible example.
Step 2: list the usual suspects: copying commands without understanding them, dangerous wildcard use, and undocumented scripts.
Step 3: revisit aliases and pipes, since misunderstandings there cause many bugs.
Step 4: use bash or similar tools to look inside.
Step 5: write a test that fails because of the bug and passes after the fix.

Many bugs involving Command Line Productivity in work such as automating repetitive tasks come down to the first suspect on the list. Check the simple causes before suspecting anything exotic.

Finally, turn commands you repeat into small scripts. It prevents a surprising number of repeat problems.
