Distributed Locks vs Event Sourcing: Which One Should You Learn First?

Learners often ask whether to study Distributed Locks or Event Sourcing first. Both sit in the area of Distributed Systems, so the honest answer is that it depends on your goals.

Distributed Locks is mechanisms that ensure only one process at a time performs a critical action across machines, and it is closely tied to lease times and fencing tokens. Event Sourcing, by contrast, is a design in which every change is stored as an immutable event and state is rebuilt from them, and it is closely tied to event log and projections.

Choose Distributed Locks first if you care about running scheduled jobs once or protecting shared resources. Choose Event Sourcing first if you care about audit trails or financial ledgers.

Think of Distributed Locks as a single key to a shared meeting room that expires automatically, and of Event Sourcing as a bank statement that lists every transaction instead of only the balance. The two pictures are very different, which is a useful reminder that the topics solve different problems.

Both have traps. With Distributed Locks, avoid locks that never expire. With Event Sourcing, avoid changing event formats carelessly.

A good habit for Distributed Locks is to always use a timeout together with a fencing token. A good habit for Event Sourcing is to version your events from the first day.
