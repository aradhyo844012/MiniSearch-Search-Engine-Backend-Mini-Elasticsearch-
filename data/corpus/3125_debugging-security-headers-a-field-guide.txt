Debugging Security Headers: A Field Guide

When something goes wrong around Security Headers, resist the urge to guess. Work through the problem in order.

Step 1: reproduce the problem with the smallest possible example.
Step 2: list the usual suspects: setting headers on only some routes, breaking embeds, and copying configurations without understanding them.
Step 3: revisit Strict-Transport-Security and X-Content-Type-Options, since misunderstandings there cause many bugs.
Step 4: use securityheaders.com or similar tools to look inside.
Step 5: write a test that fails because of the bug and passes after the fix.

Many bugs involving Security Headers in work such as hardening websites come down to the first suspect on the list. Check the simple causes before suspecting anything exotic.

Finally, test the headers on every environment. It prevents a surprising number of repeat problems.
