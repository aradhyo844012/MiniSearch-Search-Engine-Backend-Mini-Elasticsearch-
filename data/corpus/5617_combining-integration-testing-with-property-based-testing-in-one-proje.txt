Combining Integration Testing with Property-Based Testing in One Project

Real projects rarely use one idea in isolation. This article shows how Integration Testing and Property-Based Testing can work together in a single project.

Integration Testing is tests that check how several parts of a system work together. Property-Based Testing is testing with many automatically generated inputs to check that general rules always hold.

Imagine a project that involves verifying API and database interaction and testing parsers. Integration Testing brings test databases, while Property-Based Testing brings properties.

A sensible plan is to start with Testcontainers for the Integration Testing part and Hypothesis for the Property-Based Testing part, and to keep the two sides connected through a small, well-tested interface.

Be prepared for combined risks: flaky external dependencies on one side, and slow generators on the other.

Picture the whole as checking that the gears of a watch mesh before closing the case, working alongside a robot tester trying thousands of odd inputs.

Two habits help: first, use disposable containers for test dependencies; second, save failing examples as regular tests.
