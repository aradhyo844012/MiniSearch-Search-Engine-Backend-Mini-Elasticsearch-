How HTTP and HTTPS Connects to IP Addressing and Subnets

HTTP and HTTPS and IP Addressing and Subnets are closely connected parts of Networking. Seeing how they fit together helps you learn both faster.

A project involving loading web pages may also involve planning office networks. In such a project, methods and IPv4 and IPv6 often influence each other.

Start with HTTP and HTTPS: the term refers to the request and response protocol of the web, with HTTPS adding encryption. Then look at IP Addressing and Subnets, which refers to the rules for numbering devices on a network and dividing networks into smaller parts.

A useful exercise is to take one example, such as calling APIs, and explain how subnet masks would change the design.

Common problems are shared too. For HTTP and HTTPS, watch for this: sending secrets in URLs. For IP Addressing and Subnets, watch for this: miscounting host bits. Every web request crosses several layers of protocols before it reaches an application.

Spend a few hours on each topic, then combine them in one small project using curl or ipcalc.
