Combining gRPC with API Versioning in One Project

Real projects rarely use one idea in isolation. This article shows how gRPC and API Versioning can work together in a single project.

gRPC is a framework for fast remote procedure calls using typed contracts. API Versioning is the practice of evolving an API without breaking existing clients.

Imagine a project that involves service-to-service calls and public APIs. gRPC brings protocol buffers, while API Versioning brings version in the URL.

A sensible plan is to start with protoc for the gRPC part and OpenAPI for the API Versioning part, and to keep the two sides connected through a small, well-tested interface.

Be prepared for combined risks: poor browser support without a proxy on one side, and removing fields without notice on the other.

Picture the whole as a phone line with a pre-agreed script for every call, working alongside keeping old editions of a textbook available while a new one is published.

Two habits help: first, never reuse or renumber field numbers in a proto file; second, announce deprecations with a clear sunset date.
