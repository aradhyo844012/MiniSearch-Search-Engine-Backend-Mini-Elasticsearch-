Combining Go Goroutines with C Pointers in One Project

Real projects rarely use one idea in isolation. This article shows how Go Goroutines and C Pointers can work together in a single project.

Go Goroutines is lightweight threads managed by the Go runtime that run functions concurrently. C Pointers is variables that store the memory address of another value.

Imagine a project that involves servers handling many connections and dynamic memory allocation. Go Goroutines brings goroutines, while C Pointers brings addresses.

A sensible plan is to start with the go command for the Go Goroutines part and GCC for the C Pointers part, and to keep the two sides connected through a small, well-tested interface.

Be prepared for combined risks: data races on one side, and memory leaks on the other.

Picture the whole as a small crew of waiters passing notes through a serving hatch, working alongside a street address written on a card instead of the house itself.

Two habits help: first, run your tests with the race detector turned on; second, set pointers to NULL after freeing them.
