Questions to Ask About SOLID Principles in Code Review

Reviewing code that involves SOLID Principles is easier with a short list of questions. Keep these in mind as you read the diff.

- Does this change respect single responsibility, or does it work around it?
- Have we considered applying them rigidly to tiny scripts?
- Would a test catch creating too many tiny classes if it appeared later?
- Could we apply them when a design starts to hurt, not before?
- Have we avoided this problem: confusing interfaces with inheritance?
- Is UML diagrams used consistently, or are we mixing approaches?

Good reviews of work on SOLID Principles are specific, kind and focused on Liskov substitution, not on personal style.
