Everything You Need to Know About Event Sourcing

This page collects the essentials about Event Sourcing in one place. In short, Event Sourcing is a design in which every change is stored as an immutable event and state is rebuilt from them.

Core concepts:
- event log
- projections
- snapshots
- replay

Where it is used:
- audit trails
- financial ledgers
- rebuilding read models

Common problems:
- changing event formats carelessly
- unbounded replay times
- using it for simple CRUD apps

Tools to know:
- Apache Kafka
- EventStoreDB
- PostgreSQL

Remember this above all: a bank statement that lists every transaction instead of only the balance is a good way to picture it, and the best habit is to version your events from the first day.
