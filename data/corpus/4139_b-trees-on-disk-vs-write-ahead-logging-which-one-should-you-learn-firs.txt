B-Trees on Disk vs Write-Ahead Logging: Which One Should You Learn First?

Learners often ask whether to study B-Trees on Disk or Write-Ahead Logging first. Both sit in the area of Storage Engines and Databases, so the honest answer is that it depends on your goals.

B-Trees on Disk is balanced tree structures designed to read large blocks from disk efficiently, and it is closely tied to pages and branching factor. Write-Ahead Logging, by contrast, is a technique that records changes in a log before they are applied to the main data, and it is closely tied to log records and checkpoints.

Choose B-Trees on Disk first if you care about database indexes or file system directories. Choose Write-Ahead Logging first if you care about surviving crashes or feeding replication streams.

Think of B-Trees on Disk as a filing cabinet where each drawer tells you which drawer to open next, and of Write-Ahead Logging as writing a plan in a notebook before changing the real blueprint. The two pictures are very different, which is a useful reminder that the topics solve different problems.

Both have traps. With B-Trees on Disk, avoid random writes on fragmented pages. With Write-Ahead Logging, avoid disabling fsync for speed.

A good habit for B-Trees on Disk is to keep indexed keys short so more of them fit on a page. A good habit for Write-Ahead Logging is to test crash recovery by killing the process on purpose.
