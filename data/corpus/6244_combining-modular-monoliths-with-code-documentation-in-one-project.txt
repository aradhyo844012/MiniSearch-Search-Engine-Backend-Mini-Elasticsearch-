Combining Modular Monoliths with Code Documentation in One Project

Real projects rarely use one idea in isolation. This article shows how Modular Monoliths and Code Documentation can work together in a single project.

Modular Monoliths is single deployable applications built from well-separated internal modules. Code Documentation is written explanations that help others understand and use code.

Imagine a project that involves small teams and onboarding new developers. Modular Monoliths brings module boundaries, while Code Documentation brings README files.

A sensible plan is to start with ArchUnit for the Modular Monoliths part and Sphinx for the Code Documentation part, and to keep the two sides connected through a small, well-tested interface.

Be prepared for combined risks: no enforced boundaries on one side, and comments that repeat the code on the other.

Picture the whole as an apartment building with separate flats under one roof, working alongside a map left for the next traveler.

Two habits help: first, enforce boundaries with automated checks; second, keep documentation in the same repository as the code.
