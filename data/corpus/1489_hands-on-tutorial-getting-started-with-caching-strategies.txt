Hands-On Tutorial: Getting Started with Caching Strategies

This hands-on tutorial takes you from zero to a small working experiment with Caching Strategies. If you build software for long enough, you will run into Caching Strategies. The term refers to approaches for storing computed results so they can be reused instead of recalculated.

Automate repetitive steps so that results are easy to reproduce. Write a few tests that show how Caching Strategies should behave. Tests double as documentation for your teammates.

Step 1: Install or open Redis and create a new empty project folder.
Step 2: Read about cache-aside and write down a definition in your own words.
Step 3: Build the smallest possible example that uses write-through.
Step 4: Add one test or print statement that proves it works.
Step 5: Extend the example to handle a case such as speeding up read-heavy APIs.
Step 6: Break your example on purpose and see what happens. A good experiment: stale data.

Popular tools and libraries include Redis, Memcached, and HTTP cache headers.

Watch out for these problems: stale data; cache stampedes; and unbounded memory use.

Keep experimenting, keep notes, and revisit Caching Strategies whenever a new project gives you a reason.
