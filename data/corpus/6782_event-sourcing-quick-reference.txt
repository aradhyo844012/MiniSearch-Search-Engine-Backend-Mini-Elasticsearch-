Event Sourcing Quick Reference

A one-screen reminder for Event Sourcing. Bookmark it and return when the details fade.

What it is: a design in which every change is stored as an immutable event and state is rebuilt from them.
Key terms: event log, projections, snapshots, and replay.
Typical uses: audit trails, financial ledgers, and rebuilding read models.
Risks: changing event formats carelessly, unbounded replay times, and using it for simple CRUD apps.
Tools: Apache Kafka, EventStoreDB, and PostgreSQL.

Mental picture: a bank statement that lists every transaction instead of only the balance.

Habit to build: version your events from the first day.

See also: Idempotency, which sits close to Event Sourcing in the area of Distributed Systems.
