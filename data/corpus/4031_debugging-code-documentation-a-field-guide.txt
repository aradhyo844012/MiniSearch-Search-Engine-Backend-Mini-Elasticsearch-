Debugging Code Documentation: A Field Guide

When something goes wrong around Code Documentation, resist the urge to guess. Work through the problem in order.

Step 1: reproduce the problem with the smallest possible example.
Step 2: list the usual suspects: outdated docs, comments that repeat the code, and missing examples.
Step 3: revisit README files and docstrings, since misunderstandings there cause many bugs.
Step 4: use Sphinx or similar tools to look inside.
Step 5: write a test that fails because of the bug and passes after the fix.

Many bugs involving Code Documentation in work such as onboarding new developers come down to the first suspect on the list. Check the simple causes before suspecting anything exotic.

Finally, keep documentation in the same repository as the code. It prevents a surprising number of repeat problems.
