Questions to Ask About Apache Spark in Code Review

Reviewing code that involves Apache Spark is easier with a short list of questions. Keep these in mind as you read the diff.

- Is transformations and actions clear to someone reading the code for the first time?
- Have we avoided this problem: collecting huge results onto the driver?
- Would a test catch too many small partitions if it appeared later?
- Does the code handle the case of large ETL jobs correctly?
- Could we avoid collecting large results onto a single machine?
- Have we considered data skew?

Good reviews of work on Apache Spark are specific, kind and focused on partitions, not on personal style.
