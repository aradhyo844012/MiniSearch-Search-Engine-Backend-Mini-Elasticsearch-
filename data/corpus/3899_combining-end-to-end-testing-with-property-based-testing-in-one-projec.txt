Combining End-to-End Testing with Property-Based Testing in One Project

Real projects rarely use one idea in isolation. This article shows how End-to-End Testing and Property-Based Testing can work together in a single project.

End-to-End Testing is tests that drive an application through a real user journey from start to finish. Property-Based Testing is testing with many automatically generated inputs to check that general rules always hold.

Imagine a project that involves checking login and checkout flows and testing parsers. End-to-End Testing brings browser automation, while Property-Based Testing brings properties.

A sensible plan is to start with Playwright for the End-to-End Testing part and Hypothesis for the Property-Based Testing part, and to keep the two sides connected through a small, well-tested interface.

Be prepared for combined risks: slow runs on one side, and slow generators on the other.

Picture the whole as a test drive of the whole car on a real road, working alongside a robot tester trying thousands of odd inputs.

Two habits help: first, cover only the most important user journeys; second, save failing examples as regular tests.
