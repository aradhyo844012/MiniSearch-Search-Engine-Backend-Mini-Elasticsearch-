Combining A/B Testing with Feature Stores in One Project

Real projects rarely use one idea in isolation. This article shows how A/B Testing and Feature Stores can work together in a single project.

A/B Testing is an experiment that compares two versions of something to see which performs better. Feature Stores is systems that store and serve the input variables used by machine learning models.

Imagine a project that involves testing page designs and sharing features across models. A/B Testing brings control and variant, while Feature Stores brings offline store.

A sensible plan is to start with Optimizely for the A/B Testing part and Feast for the Feature Stores part, and to keep the two sides connected through a small, well-tested interface.

Be prepared for combined risks: testing too many variants on one side, and duplicate definitions on the other.

Picture the whole as taste-testing two recipes on randomly chosen guests, working alongside a shared pantry of prepared ingredients for many recipes.

Two habits help: first, decide the success metric and sample size before you begin; second, define each feature once and reuse it in training and serving.
