Python Virtual Environments Tips from Experienced Engineers

Engineers who work with Python Virtual Environments regularly tend to repeat the same advice. Here it is.

1. Make sure you can create one environment per project and record its requirements.
2. Write down why you chose Python Virtual Environments so the next person understands the decision.
3. Do not skip venv; everything else builds on it.
4. Test the case of keeping projects separate early, before the design hardens.
5. When something behaves strangely, revisit pip before anything else.

None of these tips needs special equipment, and all of them apply to reproducing setups as well as to Python Virtual Environments in general.
