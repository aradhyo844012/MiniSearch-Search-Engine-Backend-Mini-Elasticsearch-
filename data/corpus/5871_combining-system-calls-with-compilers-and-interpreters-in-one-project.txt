Combining System Calls with Compilers and Interpreters in One Project

Real projects rarely use one idea in isolation. This article shows how System Calls and Compilers and Interpreters can work together in a single project.

System Calls is the controlled doorway through which programs ask the operating system to do privileged work. Compilers and Interpreters is programs that translate or run source code written in a high-level language.

Imagine a project that involves reading and writing files and running Python and JavaScript. System Calls brings user mode and kernel mode, while Compilers and Interpreters brings lexing.

A sensible plan is to start with strace for the System Calls part and GCC for the Compilers and Interpreters part, and to keep the two sides connected through a small, well-tested interface.

Be prepared for combined risks: making too many small calls on one side, and ignoring compiler warnings on the other.

Picture the whole as a service window where a customer asks staff to do things in the back office, working alongside a translator who either translates a whole book first or interprets sentence by sentence.

Two habits help: first, use strace to see what your program really asks the kernel to do; second, turn on compiler warnings and treat them seriously.
