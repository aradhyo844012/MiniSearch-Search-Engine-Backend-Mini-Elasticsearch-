Questions to Ask About Test-Driven Development in Code Review

Reviewing code that involves Test-Driven Development is easier with a short list of questions. Keep these in mind as you read the diff.

- Does the code handle the case of designing small modules correctly?
- Is small steps clear to someone reading the code for the first time?
- Would a test catch skipping the refactor step if it appeared later?
- Have we avoided this problem: testing implementation details?
- Is pytest used consistently, or are we mixing approaches?
- Have we considered writing tests that are too large?

Good reviews of work on Test-Driven Development are specific, kind and focused on test first, not on personal style.
