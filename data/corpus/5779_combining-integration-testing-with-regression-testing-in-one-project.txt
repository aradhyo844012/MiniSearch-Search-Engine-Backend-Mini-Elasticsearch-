Combining Integration Testing with Regression Testing in One Project

Real projects rarely use one idea in isolation. This article shows how Integration Testing and Regression Testing can work together in a single project.

Integration Testing is tests that check how several parts of a system work together. Regression Testing is re-running tests after changes to make sure old features still work.

Imagine a project that involves verifying API and database interaction and protecting releases. Integration Testing brings test databases, while Regression Testing brings test suites.

A sensible plan is to start with Testcontainers for the Integration Testing part and pytest for the Regression Testing part, and to keep the two sides connected through a small, well-tested interface.

Be prepared for combined risks: flaky external dependencies on one side, and missing tests for fixed bugs on the other.

Picture the whole as checking that the gears of a watch mesh before closing the case, working alongside rechecking the old keys after cutting a new lock.

Two habits help: first, use disposable containers for test dependencies; second, add a test for every bug you fix.
