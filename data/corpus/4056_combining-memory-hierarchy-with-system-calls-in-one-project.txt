Combining Memory Hierarchy with System Calls in One Project

Real projects rarely use one idea in isolation. This article shows how Memory Hierarchy and System Calls can work together in a single project.

Memory Hierarchy is the layers of storage from registers to disks, trading speed for size. System Calls is the controlled doorway through which programs ask the operating system to do privileged work.

Imagine a project that involves designing efficient programs and reading and writing files. Memory Hierarchy brings registers, while System Calls brings user mode and kernel mode.

A sensible plan is to start with lscpu for the Memory Hierarchy part and strace for the System Calls part, and to keep the two sides connected through a small, well-tested interface.

Be prepared for combined risks: excessive paging on one side, and making too many small calls on the other.

Picture the whole as a kitchen with a spice rack, a pantry and a warehouse, working alongside a service window where a customer asks staff to do things in the back office.

Two habits help: first, reduce how often your program goes down to the slower layers; second, use strace to see what your program really asks the kernel to do.
