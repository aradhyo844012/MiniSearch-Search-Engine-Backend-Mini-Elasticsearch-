Combining End-to-End Testing with Fuzz Testing in One Project

Real projects rarely use one idea in isolation. This article shows how End-to-End Testing and Fuzz Testing can work together in a single project.

End-to-End Testing is tests that drive an application through a real user journey from start to finish. Fuzz Testing is feeding programs random or malformed input to uncover crashes and security bugs.

Imagine a project that involves checking login and checkout flows and testing parsers. End-to-End Testing brings browser automation, while Fuzz Testing brings input generation.

A sensible plan is to start with Playwright for the End-to-End Testing part and AFL++ for the Fuzz Testing part, and to keep the two sides connected through a small, well-tested interface.

Be prepared for combined risks: slow runs on one side, and crashes that cannot be reproduced on the other.

Picture the whole as a test drive of the whole car on a real road, working alongside shaking a machine hard to see what rattles loose.

Two habits help: first, cover only the most important user journeys; second, keep every crashing input as a regression test.
