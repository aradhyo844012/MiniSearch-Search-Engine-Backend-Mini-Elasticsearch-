Combining Raft Consensus with Consistent Hashing in One Project

Real projects rarely use one idea in isolation. This article shows how Raft Consensus and Consistent Hashing can work together in a single project.

Raft Consensus is an algorithm that lets a group of servers agree on a shared log of operations. Consistent Hashing is a way of mapping keys to servers so that adding or removing servers moves very few keys.

Imagine a project that involves configuration stores and distributed caches. Raft Consensus brings leader election, while Consistent Hashing brings hash ring.

A sensible plan is to start with etcd for the Raft Consensus part and Redis Cluster for the Consistent Hashing part, and to keep the two sides connected through a small, well-tested interface.

Be prepared for combined risks: slow disks causing elections on one side, and uneven load on the other.

Picture the whole as a committee that elects a chair and only records decisions most members confirm, working alongside seats around a round table where a new guest only displaces their neighbor.

Two habits help: first, use an odd number of nodes; second, use many virtual nodes per server to even out the load.
