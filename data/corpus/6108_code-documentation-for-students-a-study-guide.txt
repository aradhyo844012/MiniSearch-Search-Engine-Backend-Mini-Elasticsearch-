Code Documentation for Students: A Study Guide

This study guide prepares you for exams, labs and interviews that cover Code Documentation.

Learning goals:
1. Explain Code Documentation in your own words.
2. Describe README files, docstrings, architecture notes, and examples.
3. Give examples from onboarding new developers and describing APIs.
4. Name three problems to watch for.

Start with the definition: Code Documentation is written explanations that help others understand and use code. Then draw a map left for the next traveler on paper and label the four terms from the goals above.

Self-test questions: Why is outdated docs a problem? How does docstrings relate to architecture notes? When would you choose Sphinx or MkDocs?

Study habit: keep documentation in the same repository as the code.

When you feel ready, compare Code Documentation with API Design Principles and write down three differences.
