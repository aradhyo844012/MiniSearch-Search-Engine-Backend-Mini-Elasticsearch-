Combining Domain-Driven Design with API Design Principles in One Project

Real projects rarely use one idea in isolation. This article shows how Domain-Driven Design and API Design Principles can work together in a single project.

Domain-Driven Design is an approach to software that models the code around the real business domain. API Design Principles is guidelines for making APIs consistent, predictable and easy to use.

Imagine a project that involves complex business systems and public platforms. Domain-Driven Design brings ubiquitous language, while API Design Principles brings consistent naming.

A sensible plan is to start with event storming for the Domain-Driven Design part and OpenAPI for the API Design Principles part, and to keep the two sides connected through a small, well-tested interface.

Be prepared for combined risks: models that never match the business on one side, and inconsistent responses on the other.

Picture the whole as writing software in the same vocabulary the business speaks, working alongside the controls of a car that behave the same in every model.

Two habits help: first, agree on shared terms with domain experts before drawing classes; second, write the documentation before the implementation.
