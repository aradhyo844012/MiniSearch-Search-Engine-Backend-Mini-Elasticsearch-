How Virtual Memory Connects to Threads and Concurrency

Virtual Memory and Threads and Concurrency are closely connected parts of Operating Systems. Seeing how they fit together helps you learn both faster.

A project involving isolating programs may also involve handling many requests. In such a project, pages and threads often influence each other.

Start with Virtual Memory: the term refers to a technique that gives each program its own address space backed by RAM and disk. Then look at Threads and Concurrency, which refers to ways of making progress on several tasks at once within a program.

A useful exercise is to take one example, such as running programs larger than RAM, and explain how locks would change the design.

Common problems are shared too. For Virtual Memory, watch for this: ignoring page fault costs. For Threads and Concurrency, watch for this: creating too many threads. Resource limits such as memory, file handles and processes are easy to forget until they run out.

Spend a few hours on each topic, then combine them in one small project using vmstat or Python threading.
