Code Formatters Tips from Experienced Engineers

Engineers who work with Code Formatters regularly tend to repeat the same advice. Here it is.

1. Reach for Prettier first, and only then evaluate alternatives such as Black.
2. Do not skip style rules; everything else builds on it.
3. Test the case of ending style debates early, before the design hardens.
4. When something behaves strangely, revisit configuration before anything else.
5. Make sure you can run the formatter in a pre-commit hook.

None of these tips needs special equipment, and all of them apply to cleaner diffs as well as to Code Formatters in general.
