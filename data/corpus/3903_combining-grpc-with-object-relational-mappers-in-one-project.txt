Combining gRPC with Object-Relational Mappers in One Project

Real projects rarely use one idea in isolation. This article shows how gRPC and Object-Relational Mappers can work together in a single project.

gRPC is a framework for fast remote procedure calls using typed contracts. Object-Relational Mappers is libraries that map database tables to objects in code.

Imagine a project that involves service-to-service calls and building CRUD apps quickly. gRPC brings protocol buffers, while Object-Relational Mappers brings models.

A sensible plan is to start with protoc for the gRPC part and SQLAlchemy for the Object-Relational Mappers part, and to keep the two sides connected through a small, well-tested interface.

Be prepared for combined risks: poor browser support without a proxy on one side, and loading entire tables on the other.

Picture the whole as a phone line with a pre-agreed script for every call, working alongside a translator between the language of tables and the language of objects.

Two habits help: first, never reuse or renumber field numbers in a proto file; second, log the generated SQL during development.
