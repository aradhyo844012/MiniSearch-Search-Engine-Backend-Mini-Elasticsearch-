Combining Memory Hierarchy with GPUs and Parallelism in One Project

Real projects rarely use one idea in isolation. This article shows how Memory Hierarchy and GPUs and Parallelism can work together in a single project.

Memory Hierarchy is the layers of storage from registers to disks, trading speed for size. GPUs and Parallelism is processors with thousands of small cores that handle many similar calculations at once.

Imagine a project that involves designing efficient programs and training neural networks. Memory Hierarchy brings registers, while GPUs and Parallelism brings threads and blocks.

A sensible plan is to start with lscpu for the Memory Hierarchy part and CUDA for the GPUs and Parallelism part, and to keep the two sides connected through a small, well-tested interface.

Be prepared for combined risks: excessive paging on one side, and branch-heavy code on the other.

Picture the whole as a kitchen with a spice rack, a pantry and a warehouse, working alongside a stadium of workers each doing one small identical task.

Two habits help: first, reduce how often your program goes down to the slower layers; second, minimize copies between CPU and GPU memory.
