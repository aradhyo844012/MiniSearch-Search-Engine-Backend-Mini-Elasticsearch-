Combining Object-Relational Mappers with Configuration Management in One Project

Real projects rarely use one idea in isolation. This article shows how Object-Relational Mappers and Configuration Management can work together in a single project.

Object-Relational Mappers is libraries that map database tables to objects in code. Configuration Management is keeping application settings separate from code so they can change per environment.

Imagine a project that involves building CRUD apps quickly and separating development and production. Object-Relational Mappers brings models, while Configuration Management brings environment variables.

A sensible plan is to start with SQLAlchemy for the Object-Relational Mappers part and dotenv for the Configuration Management part, and to keep the two sides connected through a small, well-tested interface.

Be prepared for combined risks: loading entire tables on one side, and inconsistent defaults on the other.

Picture the whole as a translator between the language of tables and the language of objects, working alongside the settings dial on a machine that stays the same on every site.

Two habits help: first, log the generated SQL during development; second, fail fast at startup if a required setting is missing.
