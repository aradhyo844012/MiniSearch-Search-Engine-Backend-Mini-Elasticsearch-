Debugging State Management: A Field Guide

When something goes wrong around State Management, resist the urge to guess. Work through the problem in order.

Step 1: reproduce the problem with the smallest possible example.
Step 2: list the usual suspects: putting everything in global state, duplicated state that drifts apart, and unclear update paths.
Step 3: revisit single source of truth and actions, since misunderstandings there cause many bugs.
Step 4: use Redux or similar tools to look inside.
Step 5: write a test that fails because of the bug and passes after the fix.

Many bugs involving State Management in work such as large single-page apps come down to the first suspect on the list. Check the simple causes before suspecting anything exotic.

Finally, keep state as close as possible to where it is used. It prevents a surprising number of repeat problems.
