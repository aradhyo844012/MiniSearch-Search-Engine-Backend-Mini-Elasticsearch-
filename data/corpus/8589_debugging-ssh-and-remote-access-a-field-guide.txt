Debugging SSH and Remote Access: A Field Guide

When something goes wrong around SSH and Remote Access, resist the urge to guess. Work through the problem in order.

Step 1: reproduce the problem with the smallest possible example.
Step 2: list the usual suspects: password logins left enabled, sharing private keys, and ignoring host key warnings.
Step 3: revisit key pairs and host keys, since misunderstandings there cause many bugs.
Step 4: use OpenSSH or similar tools to look inside.
Step 5: write a test that fails because of the bug and passes after the fix.

Many bugs involving SSH and Remote Access in work such as administering servers come down to the first suspect on the list. Check the simple causes before suspecting anything exotic.

Finally, use key-based login and disable password authentication. It prevents a surprising number of repeat problems.
