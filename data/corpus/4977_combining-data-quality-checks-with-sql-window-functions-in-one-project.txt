Combining Data Quality Checks with SQL Window Functions in One Project

Real projects rarely use one idea in isolation. This article shows how Data Quality Checks and SQL Window Functions can work together in a single project.

Data Quality Checks is automated tests that verify data is complete, valid and consistent. SQL Window Functions is SQL features that calculate values across related rows without collapsing them.

Imagine a project that involves protecting dashboards and running totals. Data Quality Checks brings null checks, while SQL Window Functions brings the OVER clause.

A sensible plan is to start with Great Expectations for the Data Quality Checks part and PostgreSQL for the SQL Window Functions part, and to keep the two sides connected through a small, well-tested interface.

Be prepared for combined risks: checks only at the end of pipelines on one side, and confusing them with GROUP BY on the other.

Picture the whole as a quality inspector at the end of an assembly line, working alongside looking at the neighbors in a line without leaving your place.

Two habits help: first, check data as early as it enters the pipeline; second, start with ROW_NUMBER and LAG on a small table.
