Combining CPU Caches with System Calls in One Project

Real projects rarely use one idea in isolation. This article shows how CPU Caches and System Calls can work together in a single project.

CPU Caches is small, fast memory close to the processor that stores recently used data. System Calls is the controlled doorway through which programs ask the operating system to do privileged work.

Imagine a project that involves speeding up loops and reading and writing files. CPU Caches brings cache lines, while System Calls brings user mode and kernel mode.

A sensible plan is to start with perf for the CPU Caches part and strace for the System Calls part, and to keep the two sides connected through a small, well-tested interface.

Be prepared for combined risks: poor access patterns on one side, and making too many small calls on the other.

Picture the whole as keeping your most-used books on your desk instead of in the library, working alongside a service window where a customer asks staff to do things in the back office.

Two habits help: first, access arrays in the order they are stored; second, use strace to see what your program really asks the kernel to do.
