Debugging Cloud-Native Applications: A Field Guide

When something goes wrong around Cloud-Native Applications, resist the urge to guess. Work through the problem in order.

Step 1: reproduce the problem with the smallest possible example.
Step 2: list the usual suspects: treating the cloud like a data center, too many services, and ignoring costs.
Step 3: revisit containers and microservices, since misunderstandings there cause many bugs.
Step 4: use Kubernetes or similar tools to look inside.
Step 5: write a test that fails because of the bug and passes after the fix.

Many bugs involving Cloud-Native Applications in work such as web platforms come down to the first suspect on the list. Check the simple causes before suspecting anything exotic.

Finally, design every service to be stateless where possible. It prevents a surprising number of repeat problems.
