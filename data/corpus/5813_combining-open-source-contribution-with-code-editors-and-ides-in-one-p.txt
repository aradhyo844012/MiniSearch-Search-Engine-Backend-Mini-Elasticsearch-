Combining Open Source Contribution with Code Editors and IDEs in One Project

Real projects rarely use one idea in isolation. This article shows how Open Source Contribution and Code Editors and IDEs can work together in a single project.

Open Source Contribution is helping improve public software projects by fixing bugs, writing documentation or adding features. Code Editors and IDEs is tools for writing, navigating and debugging code.

Imagine a project that involves building a portfolio and daily development. Open Source Contribution brings forks, while Code Editors and IDEs brings syntax highlighting.

A sensible plan is to start with GitHub for the Open Source Contribution part and VS Code for the Code Editors and IDEs part, and to keep the two sides connected through a small, well-tested interface.

Be prepared for combined risks: ignoring contribution rules on one side, and ignoring keyboard shortcuts on the other.

Picture the whole as helping repair a shared public library, working alongside a well-organized workbench.

Two habits help: first, start with documentation fixes or small bugs; second, learn the shortcuts for the actions you repeat most.
