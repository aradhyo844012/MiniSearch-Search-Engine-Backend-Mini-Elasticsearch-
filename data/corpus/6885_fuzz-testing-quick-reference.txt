Fuzz Testing Quick Reference

A one-screen reminder for Fuzz Testing. Bookmark it and return when the details fade.

What it is: feeding programs random or malformed input to uncover crashes and security bugs.
Key terms: input generation, coverage guidance, crash triage, and corpora.
Typical uses: testing parsers, finding memory bugs, and security research.
Risks: running without sanitizers, crashes that cannot be reproduced, and ignoring slow inputs.
Tools: AFL++, libFuzzer, and Atheris.

Mental picture: shaking a machine hard to see what rattles loose.

Habit to build: keep every crashing input as a regression test.

See also: Regression Testing, which sits close to Fuzz Testing in the area of Testing and Quality.
