Combining SOLID Principles with API Design Principles in One Project

Real projects rarely use one idea in isolation. This article shows how SOLID Principles and API Design Principles can work together in a single project.

SOLID Principles is five guidelines for designing object-oriented code that is easy to change. API Design Principles is guidelines for making APIs consistent, predictable and easy to use.

Imagine a project that involves structuring classes and public platforms. SOLID Principles brings single responsibility, while API Design Principles brings consistent naming.

A sensible plan is to start with UML diagrams for the SOLID Principles part and OpenAPI for the API Design Principles part, and to keep the two sides connected through a small, well-tested interface.

Be prepared for combined risks: creating too many tiny classes on one side, and inconsistent responses on the other.

Picture the whole as house rules that keep a shared kitchen tidy, working alongside the controls of a car that behave the same in every model.

Two habits help: first, apply them when a design starts to hurt, not before; second, write the documentation before the implementation.
