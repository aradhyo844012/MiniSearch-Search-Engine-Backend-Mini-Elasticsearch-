Best Practices for NoSQL Databases

The practices below come from patterns that tend to work well across many teams and projects. If you build software for long enough, you will run into NoSQL Databases. The term refers to a broad family of databases that do not use the traditional relational table model.

1. Automate repetitive steps so that results are easy to reproduce.
2. Keep notes on what worked. A short README explaining your decisions about NoSQL Databases helps the next developer.
3. Write a few tests that show how NoSQL Databases should behave. Tests double as documentation for your teammates.
4. Read the official documentation for Cassandra; it often explains key-value stores better than blog posts do.
5. Start small by applying NoSQL Databases to one case, such as flexible schemas, before rolling it out more widely.
