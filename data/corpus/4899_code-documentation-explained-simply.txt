Code Documentation Explained Simply

Here is Code Documentation without the jargon: it is written explanations that help others understand and use code.

Think of Code Documentation as a map left for the next traveler. Keep that picture in mind as you read on.

The vocabulary has four main pieces: README files, docstrings, architecture notes, and examples. You do not need to master them all at once. Start with README files, then add docstrings.

People reach for Code Documentation when they work on onboarding new developers, describing APIs, and recording design decisions.

One practical tip is to keep documentation in the same repository as the code.
