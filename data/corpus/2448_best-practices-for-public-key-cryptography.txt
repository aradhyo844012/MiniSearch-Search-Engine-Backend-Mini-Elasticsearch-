Best Practices for Public Key Cryptography

The practices below come from patterns that tend to work well across many teams and projects. When people talk about Public Key Cryptography, they usually mean encryption that uses a pair of keys, one public and one private. It appears in almost every serious software project, whether or not developers notice it.

1. Start small by applying Public Key Cryptography to one case, such as HTTPS, before rolling it out more widely.
2. Keep notes on what worked. A short README explaining your decisions about Public Key Cryptography helps the next developer.
3. Read the official documentation for GnuPG; it often explains digital signatures better than blog posts do.
4. Automate repetitive steps so that results are easy to reproduce.
5. Keep an eye on this risk during code review: losing private keys.

Public Key Cryptography and Secure Coding are closely related, so learning both gives a fuller picture of Security.

Popular tools and libraries include OpenSSL, GnuPG, and SSH keys.

A solid grasp of Public Key Cryptography also makes Secure Coding easier to understand.

None of this needs special hardware or expensive software. A laptop, curiosity and a few small experiments are enough to get comfortable with Public Key Cryptography.
