Combining Jupyter Notebooks with SQL Window Functions in One Project

Real projects rarely use one idea in isolation. This article shows how Jupyter Notebooks and SQL Window Functions can work together in a single project.

Jupyter Notebooks is interactive documents that combine code, results and notes. SQL Window Functions is SQL features that calculate values across related rows without collapsing them.

Imagine a project that involves exploring data and running totals. Jupyter Notebooks brings cells, while SQL Window Functions brings the OVER clause.

A sensible plan is to start with JupyterLab for the Jupyter Notebooks part and PostgreSQL for the SQL Window Functions part, and to keep the two sides connected through a small, well-tested interface.

Be prepared for combined risks: hidden state on one side, and confusing them with GROUP BY on the other.

Picture the whole as a lab notebook that can run its own experiments, working alongside looking at the neighbors in a line without leaving your place.

Two habits help: first, restart the kernel and run all cells before sharing; second, start with ROW_NUMBER and LAG on a small table.
