A Practical Checklist for Load Balancing

Use this checklist before you rely on Load Balancing in a project.

1. Measure results before and after any change.
2. Pick a tool to start with, such as NGINX or HAProxy.
3. Document your decisions in the project README.
4. Guard against this risk: the balancer becoming a single point of failure.
5. Review how Load Balancing interacts with DNS.
6. Write at least one automated test that covers round robin.
7. Try the approach on a small case, for example scaling web applications.
8. Guard against this risk: session data stored only on one server.
