Questions to Ask About systemd Services in Code Review

Reviewing code that involves systemd Services is easier with a short list of questions. Keep these in mind as you read the diff.

- Could we run systemctl daemon-reload after every unit file change?
- Would a test catch missing restart policies if it appeared later?
- Does this change respect unit files, or does it work around it?
- Have we considered editing unit files without reloading the daemon?
- Is targets clear to someone reading the code for the first time?
- Have we avoided this problem: ignoring dependency ordering?

Good reviews of work on systemd Services are specific, kind and focused on service states, not on personal style.
