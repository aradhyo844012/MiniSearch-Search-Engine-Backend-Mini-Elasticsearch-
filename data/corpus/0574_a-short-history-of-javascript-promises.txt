A Short History of JavaScript Promises

Ideas behind JavaScript Promises developed gradually as engineers ran into practical limits and shared what they learned. If you build software for long enough, you will run into JavaScript Promises. The term refers to objects that represent a value that will be available later, after an asynchronous task finishes.

Web pages must work across many browsers, devices and network conditions.

The vocabulary of JavaScript Promises is small. Learn pending and resolved states, then and catch, async and await, and chaining, and most documentation will start to make sense. Sketching chaining on paper before coding helps many learners see how the pieces fit.

A solid grasp of JavaScript Promises also makes Single Page Applications easier to understand.

With steady practice, JavaScript Promises will stop feeling abstract and become a tool you reach for naturally.
