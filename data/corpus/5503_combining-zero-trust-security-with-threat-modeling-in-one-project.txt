Combining Zero Trust Security with Threat Modeling in One Project

Real projects rarely use one idea in isolation. This article shows how Zero Trust Security and Threat Modeling can work together in a single project.

Zero Trust Security is a model that treats every request as untrusted until it is verified. Threat Modeling is a structured way of identifying what could go wrong in a system and how to prevent it.

Imagine a project that involves remote work access and designing new features. Zero Trust Security brings identity verification, while Threat Modeling brings assets.

A sensible plan is to start with Okta for the Zero Trust Security part and STRIDE for the Threat Modeling part, and to keep the two sides connected through a small, well-tested interface.

Be prepared for combined risks: poor identity hygiene on one side, and ignoring data flows on the other.

Picture the whole as a building where every door checks your badge, not just the front entrance, working alongside walking around a house asking where a burglar might get in.

Two habits help: first, start with strong identity and device checks; second, draw the data flow diagram first.
