Combining Hexagonal Architecture with API Design Principles in One Project

Real projects rarely use one idea in isolation. This article shows how Hexagonal Architecture and API Design Principles can work together in a single project.

Hexagonal Architecture is a design that keeps core logic separate from outside systems through ports and adapters. API Design Principles is guidelines for making APIs consistent, predictable and easy to use.

Imagine a project that involves testable business logic and public platforms. Hexagonal Architecture brings ports, while API Design Principles brings consistent naming.

A sensible plan is to start with Spring for the Hexagonal Architecture part and OpenAPI for the API Design Principles part, and to keep the two sides connected through a small, well-tested interface.

Be prepared for combined risks: leaking framework types into the core on one side, and inconsistent responses on the other.

Picture the whole as a power strip that lets any plug connect to the same core, working alongside the controls of a car that behave the same in every model.

Two habits help: first, keep framework imports out of the core domain; second, write the documentation before the implementation.
