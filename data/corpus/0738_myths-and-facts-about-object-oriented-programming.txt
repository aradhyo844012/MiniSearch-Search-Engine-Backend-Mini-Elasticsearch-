Myths and Facts About Object-Oriented Programming

A lot of folklore has built up around Object-Oriented Programming. Some of it is true, and some of it is not. Many students first meet Object-Oriented Programming in a classroom, but it matters just as much in production systems. The term refers to a style of programming that organizes code into objects that combine data and behavior.

Myth: Object-Oriented Programming is only for experts.
Fact: beginners can use it effectively once they understand classes and inheritance.

Myth: Object-Oriented Programming is only useful in very large systems.
Fact: small projects such as modeling real-world entities benefit as well.

Myth: one tool does everything.
Fact: Python classes, Java, and UML tools make different trade-offs, so the right choice depends on the project.

Myth: mistakes with Object-Oriented Programming are always obvious.
Fact: subtle problems happen, for example deep inheritance chains.

Keep experimenting, keep notes, and revisit Object-Oriented Programming whenever a new project gives you a reason.
