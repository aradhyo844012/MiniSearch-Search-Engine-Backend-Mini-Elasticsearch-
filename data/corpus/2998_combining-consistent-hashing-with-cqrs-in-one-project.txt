Combining Consistent Hashing with CQRS in One Project

Real projects rarely use one idea in isolation. This article shows how Consistent Hashing and CQRS can work together in a single project.

Consistent Hashing is a way of mapping keys to servers so that adding or removing servers moves very few keys. CQRS is a pattern that separates the models used to change data from the models used to read it.

Imagine a project that involves distributed caches and high-read dashboards. Consistent Hashing brings hash ring, while CQRS brings commands.

A sensible plan is to start with Redis Cluster for the Consistent Hashing part and Axon Framework for the CQRS part, and to keep the two sides connected through a small, well-tested interface.

Be prepared for combined risks: uneven load on one side, and read models drifting out of sync on the other.

Picture the whole as seats around a round table where a new guest only displaces their neighbor, working alongside a restaurant with one counter for orders and another for pickup.

Two habits help: first, use many virtual nodes per server to even out the load; second, start with a single model and split only when reads and writes truly diverge.
