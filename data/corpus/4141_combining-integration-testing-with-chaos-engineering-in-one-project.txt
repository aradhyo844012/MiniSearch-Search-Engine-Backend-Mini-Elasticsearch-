Combining Integration Testing with Chaos Engineering in One Project

Real projects rarely use one idea in isolation. This article shows how Integration Testing and Chaos Engineering can work together in a single project.

Integration Testing is tests that check how several parts of a system work together. Chaos Engineering is deliberately causing failures in a system to learn how it responds.

Imagine a project that involves verifying API and database interaction and testing resilience. Integration Testing brings test databases, while Chaos Engineering brings steady state.

A sensible plan is to start with Testcontainers for the Integration Testing part and Chaos Monkey for the Chaos Engineering part, and to keep the two sides connected through a small, well-tested interface.

Be prepared for combined risks: flaky external dependencies on one side, and having no steady-state metrics on the other.

Picture the whole as checking that the gears of a watch mesh before closing the case, working alongside a fire drill where you secretly block one exit.

Two habits help: first, use disposable containers for test dependencies; second, start with small experiments in a test environment.
