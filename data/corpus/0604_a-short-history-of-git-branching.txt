A Short History of Git Branching

Ideas behind Git Branching developed gradually as engineers ran into practical limits and shared what they learned. Put simply, Git Branching covers using separate lines of development so that changes can be built and reviewed independently. Learning it well pays off across many areas of computing.

Small, frequent releases are usually safer than rare, large ones.

The vocabulary of Git Branching is small. Learn branches, merging, rebasing, and pull requests, and most documentation will start to make sense. Sketching pull requests on paper before coding helps many learners see how the pieces fit.

Git Branching and Kubernetes are closely related, so learning both gives a fuller picture of Cloud and DevOps.
