Debugging API Gateways: A Field Guide

When something goes wrong around API Gateways, resist the urge to guess. Work through the problem in order.

Step 1: reproduce the problem with the smallest possible example.
Step 2: list the usual suspects: a single point of failure, business logic leaking into the gateway, and added latency.
Step 3: revisit routing and authentication, since misunderstandings there cause many bugs.
Step 4: use Kong or similar tools to look inside.
Step 5: write a test that fails because of the bug and passes after the fix.

Many bugs involving API Gateways in work such as exposing microservices come down to the first suspect on the list. Check the simple causes before suspecting anything exotic.

Finally, keep the gateway thin and put business logic in services. It prevents a surprising number of repeat problems.
