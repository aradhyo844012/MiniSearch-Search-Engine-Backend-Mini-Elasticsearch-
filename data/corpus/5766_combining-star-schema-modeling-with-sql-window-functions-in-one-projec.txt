Combining Star Schema Modeling with SQL Window Functions in One Project

Real projects rarely use one idea in isolation. This article shows how Star Schema Modeling and SQL Window Functions can work together in a single project.

Star Schema Modeling is a way of organizing analytics data into a central fact table surrounded by dimension tables. SQL Window Functions is SQL features that calculate values across related rows without collapsing them.

Imagine a project that involves business intelligence reports and running totals. Star Schema Modeling brings fact tables, while SQL Window Functions brings the OVER clause.

A sensible plan is to start with dbt for the Star Schema Modeling part and PostgreSQL for the SQL Window Functions part, and to keep the two sides connected through a small, well-tested interface.

Be prepared for combined risks: over-normalized dimensions on one side, and confusing them with GROUP BY on the other.

Picture the whole as a wheel with a hub of numbers and spokes of descriptions, working alongside looking at the neighbors in a line without leaving your place.

Two habits help: first, state the grain of the fact table before designing anything else; second, start with ROW_NUMBER and LAG on a small table.
