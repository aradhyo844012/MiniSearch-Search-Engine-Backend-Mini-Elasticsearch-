Combining API Design Principles with Code Documentation in One Project

Real projects rarely use one idea in isolation. This article shows how API Design Principles and Code Documentation can work together in a single project.

API Design Principles is guidelines for making APIs consistent, predictable and easy to use. Code Documentation is written explanations that help others understand and use code.

Imagine a project that involves public platforms and onboarding new developers. API Design Principles brings consistent naming, while Code Documentation brings README files.

A sensible plan is to start with OpenAPI for the API Design Principles part and Sphinx for the Code Documentation part, and to keep the two sides connected through a small, well-tested interface.

Be prepared for combined risks: inconsistent responses on one side, and comments that repeat the code on the other.

Picture the whole as the controls of a car that behave the same in every model, working alongside a map left for the next traveler.

Two habits help: first, write the documentation before the implementation; second, keep documentation in the same repository as the code.
