Pair Programming Tips from Experienced Engineers

Engineers who work with Pair Programming regularly tend to repeat the same advice. Here it is.

1. Be careful with this one: one person dominating.
2. Make sure you can swap roles every twenty to thirty minutes.
3. Write down why you chose Pair Programming so the next person understands the decision.
4. Test the case of teaching new teammates early, before the design hardens.
5. Reach for VS Code Live Share first, and only then evaluate alternatives such as Tuple.

None of these tips needs special equipment, and all of them apply to solving hard bugs as well.
