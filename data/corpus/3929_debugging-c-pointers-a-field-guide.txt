Debugging C Pointers: A Field Guide

When something goes wrong around C Pointers, resist the urge to guess. Work through the problem in order.

Step 1: reproduce the problem with the smallest possible example.
Step 2: list the usual suspects: dereferencing null pointers, memory leaks, and dangling pointers.
Step 3: revisit addresses and dereferencing, since misunderstandings there cause many bugs.
Step 4: use GCC or similar tools to look inside.
Step 5: write a test that fails because of the bug and passes after the fix.

Many bugs involving C Pointers in work such as dynamic memory allocation come down to the first suspect on the list. Check the simple causes before suspecting anything exotic.

Finally, set pointers to NULL after freeing them. It prevents a surprising number of repeat problems.
