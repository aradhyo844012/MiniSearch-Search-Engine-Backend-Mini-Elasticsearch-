Questions to Ask About API Versioning in Code Review

Reviewing code that involves API Versioning is easier with a short list of questions. Keep these in mind as you read the diff.

- Is header versioning clear to someone reading the code for the first time?
- Does this change respect version in the URL, or does it work around it?
- Could we announce deprecations with a clear sunset date?
- Is OpenAPI used consistently, or are we mixing approaches?
- Would a test catch removing fields without notice if it appeared later?
- Have we avoided this problem: having no deprecation schedule?

Good reviews of work on API Versioning are specific, kind and focused on deprecation, not on personal style.
