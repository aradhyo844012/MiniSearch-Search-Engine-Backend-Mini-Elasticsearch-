Questions to Ask About Threat Modeling in Code Review

Reviewing code that involves Threat Modeling is easier with a short list of questions. Keep these in mind as you read the diff.

- Would a test catch ignoring data flows if it appeared later?
- Could we draw the data flow diagram first?
- Does this change respect assets, or does it work around it?
- Have we considered doing it once and never again?
- Is STRIDE used consistently, or are we mixing approaches?
- Have we avoided this problem: focusing only on technical threats?

Good reviews of work on Threat Modeling are specific, kind and focused on trust boundaries, not on personal style.
