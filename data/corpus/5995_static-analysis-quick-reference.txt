Static Analysis Quick Reference

A one-screen reminder for Static Analysis. Bookmark it and return when the details fade.

What it is: automated checking of source code for bugs and style problems without running it.
Key terms: linters, type checkers, rule sets, and false positives.
Typical uses: catching bugs early, enforcing team style, and improving security.
Risks: ignoring warnings, too many noisy rules, and disabling checks permanently.
Tools: ESLint, Pylint, and SonarQube.

Mental picture: a spell checker for code.

Habit to build: run it in CI so problems never reach the main branch.
