Debugging Code Coverage: A Field Guide

When something goes wrong around Code Coverage, resist the urge to guess. Work through the problem in order.

Step 1: reproduce the problem with the smallest possible example.
Step 2: list the usual suspects: chasing 100 percent, treating coverage as quality, and ignoring branch coverage.
Step 3: revisit line coverage and branch coverage, since misunderstandings there cause many bugs.
Step 4: use coverage.py or similar tools to look inside.
Step 5: write a test that fails because of the bug and passes after the fix.

Many bugs involving Code Coverage in work such as finding untested code come down to the first suspect on the list. Check the simple causes before suspecting anything exotic.

Finally, use coverage to find gaps, not to judge quality. It prevents a surprising number of repeat problems.
