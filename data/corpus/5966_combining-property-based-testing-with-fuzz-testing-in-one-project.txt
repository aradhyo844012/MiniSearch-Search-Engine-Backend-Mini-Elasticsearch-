Combining Property-Based Testing with Fuzz Testing in One Project

Real projects rarely use one idea in isolation. This article shows how Property-Based Testing and Fuzz Testing can work together in a single project.

Property-Based Testing is testing with many automatically generated inputs to check that general rules always hold. Fuzz Testing is feeding programs random or malformed input to uncover crashes and security bugs.

Imagine a project that involves testing parsers and testing parsers. Property-Based Testing brings properties, while Fuzz Testing brings input generation.

A sensible plan is to start with Hypothesis for the Property-Based Testing part and AFL++ for the Fuzz Testing part, and to keep the two sides connected through a small, well-tested interface.

Be prepared for combined risks: slow generators on one side, and crashes that cannot be reproduced on the other.

Picture the whole as a robot tester trying thousands of odd inputs, working alongside shaking a machine hard to see what rattles loose.

Two habits help: first, save failing examples as regular tests; second, keep every crashing input as a regression test.
