Questions to Ask About WebAssembly in Code Review

Reviewing code that involves WebAssembly is easier with a short list of questions. Keep these in mind as you read the diff.

- Have we considered crossing the JavaScript boundary too often?
- Would a test catch large binaries if it appeared later?
- Does this change respect modules, or does it work around it?
- Have we avoided this problem: limited access to browser APIs?
- Could we measure before moving code to WebAssembly?
- Is linear memory clear to someone reading the code for the first time?

Good reviews of work on WebAssembly are specific, kind and focused on imports and exports, not on personal style.
