Common Mistakes When Working with Authentication and Sessions

Almost everyone makes a few avoidable errors when first working with Authentication and Sessions. When people talk about Authentication and Sessions, they usually mean the process of proving who a user is and remembering them between requests. It appears in almost every serious software project, whether or not developers notice it.

Practice credentials with small exercises until it feels natural. Write a few tests that show how Authentication and Sessions should behave. Tests double as documentation for your teammates.

Watch out for these problems: storing session IDs insecurely; never expiring sessions; and trusting client-side checks.

Consider the first problem: storing session IDs insecurely. A short test or a careful review comment usually catches it. The second problem is similar: never expiring sessions. The third problem is this: trusting client-side checks. It tends to appear only once a project grows, so it is worth planning for early.
