Combining gRPC with Dependency Injection in One Project

Real projects rarely use one idea in isolation. This article shows how gRPC and Dependency Injection can work together in a single project.

gRPC is a framework for fast remote procedure calls using typed contracts. Dependency Injection is a design approach where objects receive their dependencies instead of creating them.

Imagine a project that involves service-to-service calls and easier unit testing. gRPC brings protocol buffers, while Dependency Injection brings constructor injection.

A sensible plan is to start with protoc for the gRPC part and Spring for the Dependency Injection part, and to keep the two sides connected through a small, well-tested interface.

Be prepared for combined risks: poor browser support without a proxy on one side, and circular dependencies on the other.

Picture the whole as a phone line with a pre-agreed script for every call, working alongside a chef who is handed ingredients instead of shopping for them.

Two habits help: first, never reuse or renumber field numbers in a proto file; second, inject interfaces so tests can use simple fakes.
