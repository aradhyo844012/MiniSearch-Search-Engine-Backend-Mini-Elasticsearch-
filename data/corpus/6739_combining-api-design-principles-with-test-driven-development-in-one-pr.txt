Combining API Design Principles with Test-Driven Development in One Project

Real projects rarely use one idea in isolation. This article shows how API Design Principles and Test-Driven Development can work together in a single project.

API Design Principles is guidelines for making APIs consistent, predictable and easy to use. Test-Driven Development is a workflow where you write a failing test first and then write code to make it pass.

Imagine a project that involves public platforms and designing small modules. API Design Principles brings consistent naming, while Test-Driven Development brings red, green, refactor.

A sensible plan is to start with OpenAPI for the API Design Principles part and pytest for the Test-Driven Development part, and to keep the two sides connected through a small, well-tested interface.

Be prepared for combined risks: inconsistent responses on one side, and skipping the refactor step on the other.

Picture the whole as the controls of a car that behave the same in every model, working alongside writing the exam questions before teaching the lesson.

Two habits help: first, write the documentation before the implementation; second, keep each red-green cycle to a few minutes.
