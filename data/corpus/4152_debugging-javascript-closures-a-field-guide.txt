Debugging JavaScript Closures: A Field Guide

When something goes wrong around JavaScript Closures, resist the urge to guess. Work through the problem in order.

Step 1: reproduce the problem with the smallest possible example.
Step 2: list the usual suspects: loop variables captured by mistake, memory leaks from long-lived closures, and accidentally sharing mutable state.
Step 3: revisit lexical scope and captured variables, since misunderstandings there cause many bugs.
Step 4: use Chrome DevTools or similar tools to look inside.
Step 5: write a test that fails because of the bug and passes after the fix.

Many bugs involving JavaScript Closures in work such as keeping private state in modules come down to the first suspect on the list. Check the simple causes before suspecting anything exotic.

Finally, use let instead of var inside loops. It prevents a surprising number of repeat problems.
