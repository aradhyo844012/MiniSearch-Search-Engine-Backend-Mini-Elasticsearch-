Debugging Dev Containers: A Field Guide

When something goes wrong around Dev Containers, resist the urge to guess. Work through the problem in order.

Step 1: reproduce the problem with the smallest possible example.
Step 2: list the usual suspects: slow image builds, files owned by the wrong user, and forgetting to pin tool versions.
Step 3: revisit devcontainer.json and images, since misunderstandings there cause many bugs.
Step 4: use VS Code Dev Containers or similar tools to look inside.
Step 5: write a test that fails because of the bug and passes after the fix.

Many bugs involving Dev Containers in work such as onboarding new developers come down to the first suspect on the list. Check the simple causes before suspecting anything exotic.

Finally, pin tool versions inside the container definition. It prevents a surprising number of repeat problems.
