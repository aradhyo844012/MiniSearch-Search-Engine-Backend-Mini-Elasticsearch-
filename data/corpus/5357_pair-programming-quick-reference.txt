Pair Programming Quick Reference

A one-screen reminder for Pair Programming. Bookmark it and return when the details fade.

What it is: two developers working together at one computer on the same code.
Key terms: driver and navigator, rotation, communication, and shared ownership.
Typical uses: teaching new teammates, solving hard bugs, and improving code quality.
Risks: one person dominating, fatigue from long sessions, and pairing on every task.
Tools: VS Code Live Share, Tuple, and shared terminals.

Mental picture: a pilot and co-pilot who check each other's decisions.

Habit to build: swap roles every twenty to thirty minutes.

See also: Event-Driven Architecture, which sits close to Pair Programming in the area of Software Design.
