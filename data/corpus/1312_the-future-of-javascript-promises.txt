The Future of JavaScript Promises

Predicting the future is risky, but the direction of JavaScript Promises is easy to describe in general terms. Many students first meet JavaScript Promises in a classroom, but it matters just as much in production systems. The term refers to objects that represent a value that will be available later, after an asynchronous task finishes.

Small improvements in markup and styling often have a large effect on usability.

Expect tools such as fetch API and Node.js to keep improving, and expect newer ideas to keep building on pending and resolved states. The basics, though, tend to stay the same, so time spent on then and catch and async and await is rarely wasted. Anyone working on fetching data from APIs will keep meeting JavaScript Promises for years to come.

A short README explaining your decisions about JavaScript Promises helps the next developer. Measure before you optimize. Use fetch API or a simple timer to see where time is actually spent.
